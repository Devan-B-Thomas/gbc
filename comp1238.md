## Week 1 - Information Storage Before Computers
- Cuneiform is written using wedges which are pressed into clay.
- Glyphs usually represented syllables. Original symbols usually derived from a word that started with that sound, but then evolved.
- Printing is almost as old as writing and after the Gutenburg bible was created print shops exploded onto the scene.
## Week 2 - Representing text and numbers in computers
- A bit is the tiniest piece of info in a computer, it can hold 1 of 2 possible values, and is short for binary digit.
- Volatile memory gets erased when electricity is gone. Non-volatile memory is used for long term storage.
- The computer sees the memory as one long sequence of bytes. It can look up the value in each one of the bytes.
## Week 3 - Text Structure
- The term markup comes from newspapers where the editor would "mark up" your submitted article.
- Some characters are assigned special meanings and are called special or reserved characters. If one wants to treat a special character as if it is a normal character it has to be escaped
- UTF-8 attempts to be as compatible with ASCII as possible with all 128 chars of the ASCII table being encoded exactly the same in UTF-8 and ASCII.
## Week 4 - Working With Text
- There is no perfect way to sit at a desk, be attentive to your body and if you are uncomfortable in a certain position simply move to a more comfortable one.
- Word processors uses "Rich Formatting" which is read differently the regular text you would write in a text editor. We use text editors for programming.
- RegEx is a whole language for creating search patterns. Some examples are: . = matches any character, [abc] = matches any of the listed characters, [a-z] = matches any lower-case letter, [0-9] = matches any digit, so does \d
## Week 5 - CLI: Command Line Interfaces
- Interactive Terminals were the original command line where you would type a command, press Enter, and the computer would print out a response
- Why use a CLI? Some functionality has no GUI, Precise control, Easy automation of repetitive tasks (scripting), Faster - for some types of work, Works great remotely over slow networks, Requires very little computer resources compared to GUI
- Useful commands: ls : list files in current directory, pwd : print working directory, cd : change directory, cat, less : show contents of a text file, cp, mv, mkdir : copy & move files, create a directory, ping : ping a server over the network
## Week 6 - Comparing and versioning text files: git & GitHub
- git is not the same as github, git is stored locally and deals with files saved onto your disk while github is cloud-based service designed for storing your work, sharing with others, and a ton of extra functionality on top
- The git cycle: “Pull” the latest version from the remote repo, Modify files using any editor, “Commit” your changes to your local repo “commit” as a verb = create a version, “Push” your commit to the remote repo “commit” as a noun is a synonym of “version”, repeat.
- When working in parallel with other whoever pushes first gets an "ok" response, the 2nd person gets their push declined and they must pull first, merge, then push.
